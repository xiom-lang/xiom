# v0.65.0

## Summary
A production release focused on correctness, release-build parity, and the first bare-metal microcontroller targets.

## Highlights

### Enumerate, map, and collect keep tuple values
kind: fix
Chained iterator calls now bind the mapping function's tuple return through collect, so indexed ranges keep both elements and field access reads the real payload.

### Data-loss fixes for results and tuples
kind: fix
Direct error values pushed into vectors, vectors inside cross-module result tuples, and nested enum-variant matches now preserve their payloads.

### Release builds match debug builds
kind: compiler
A release-compiler parity job now runs the correctness probes from the optimized binary on Linux, Windows, and the ARM64 compiler floor.

### Cortex-M and RISC-V microcontroller targets
kind: tooling
New freestanding targets for Cortex-M and 32-bit RISC-V ship with a startup, linker, and runtime contract, plus emulator tests.

### Lower memory use for confined loops
kind: compiler
Copying a vector out of a confined block now only copies memory owned by the block, removing a large per-iteration leak in frame capture workloads.

## Breaking changes
- None.

## Known issues
- Microcontroller targets use a bump allocator and do not support exceptions; vendor peripherals are not emulated.
