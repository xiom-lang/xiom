# v0.63.0

## Summary
A correctness and speed release: LZ4 block compression is fixed, the
contract verifier emits valid SMT-LIB, scripting no longer indexes the
system temp tree, and compile-time caches cut warm builds sharply.

## Highlights

### LZ4 block compression fixed
kind: fix
LZ4 block compression could read back an empty result in programs
compiled on v0.62.2-v0.62.4. The 2^32-element Vec growth ceiling added in
v0.62.2 lowered through a movabs and an x86 peephole pass then
miscompiled the compressor; the ceiling is now 2^32-1 elements and byte
buffers above 16 MB keep working.

### Contract verifier emits valid SMT-LIB
kind: fix
z3 verification failed to parse the generated SMT for many obligations
(duplicate named expressions, undeclared initialized/self symbols, sort
mismatches). It now produces unique labels, never emits undeclared
symbols, matches selectors, guards operators by sort, and reports
unmodeled obligations as UNKNOWN.

### xiom run no longer indexes the temp tree
kind: fix
Scripting compiled a copy under the system temp directory, and the
compiler registered the temp root as a source directory whenever a stray
.xi file sat there, indexing every unrelated tree under temp. Temp-root
ancestors are never registered now; cold script runs dropped from minutes
to seconds.

### Compile-time caches
kind: compiler
The C runtime is compiled to objects once per (clang, flags, contents)
tuple and reused, and the catalog's module-header index is cached
persistently. Measured on the dev driver: hello-world 8.7s to 0.97s warm,
the LZ4 program 13.3s to 4.0s warm.

### Verifier CLI speed and safety
kind: tooling
The standalone verifier no longer treats the temp root as a source
directory and reuses the catalog index cache: its integration suite went
from over 10 minutes (timing out) to under 8 seconds.

### Doctor and timing tooling
kind: tooling
xiom doctor compares major.minor version lines only (patch differences
and tag-shaped pins no longer warn), and XIOM_TIMINGS=1 reports the
catalog-index phase and per-module catalog check stats.

## Breaking changes

- None.

## Known issues

- iter.range.contains (C001) can fail run-to-run nondeterministically on some programs (classifier state); the standard library releases carry a documented exclusion until it is fixed.
- reflect.all_types() can corrupt the heap (catalog-return path); fix scheduled.
- Range.collect() closure forward-reference remains open on the clause side; fix scheduled.
