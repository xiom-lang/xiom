# v0.64.8

## Summary
Frame-shaped memory reuse through a scoped arena, safe i128 division in loops, faster catalog indexing, and cross-module type fixes, with the matching stdlib pin.

## Highlights

### Scoped arena for frame-shaped memory
kind: compiler
Per-frame allocations can be bounded with the runtime scoped arena: enter before a frame and exit after, and its data is reclaimed wholesale, including Vecs that cross function boundaries. A frame-style workload falls from 4.5 GB to about 50 MB and stays flat.

### Vec drops and i128 division
kind: fix
Owned Vec locals are freed at scope exit, and i128 division and modulo lower to inline long division instead of the recursive runtime helper. The loop repro stays flat and the i128 access violation is gone.

### Faster catalog indexing
kind: fix
Transient temp directories are indexed shallowly, the persistent catalog cache is per compiler version, and stale roots are pruned. A six-line file in a busy temp tree dropped from about 50 seconds of indexing to under one second.

### Cross-module type and reference fixes
kind: fix
Generic-struct Vec elements, cross-module generic aliases, module-global mutable aggregates, and three-level nested mutable field paths now resolve and mutate the intended storage.

## Breaking changes
- None.

## Known issues
- Cross-module aliases to imported structs can still fail field access; a codegen layout fix is queued for the next cycle.
- A generic call nested directly as a ptr.read argument can read the erased element type; stage the call in a local as a workaround.
- A capture-frames probe can still hang on the run leg; a minimized repro is pending.
- Send/Sync markers are declared and auto-derived but not yet enforced on every spawn capture.
- The dependency-object cache key can still be consumer-specific in multi-target builds, and a per-key lock is pending.
- The selfhost compiler remains a work in progress and is not part of this toolchain release.
