# v0.64.2

## Summary
Correctness release: vector element layout, alias and enum payloads, and reference-passing bugs are fixed, loops no longer exhaust the stack, and the CLI reports program exit codes.

## Highlights

### Vector element layout matches the compiled structs
kind: fix
Reading or assigning elements of vectors of structs now uses each struct's padded compiled layout, so a trailing flag or value after a vector-bearing field reads correctly, and assigning optional or result elements keeps the slot's tag and payload readable.

### Aliases, enum variants, and determinism
kind: fix
Match payloads behind package type aliases keep their concrete type, bare enum variants resolve to the declaring module instead of the first registered twin, and a hash-order-dependent type lookup that could flip enum field reads between builds is fixed.

### References and nested fields write through
kind: fix
Passing a byte vector by reference to string-from-bytes constructors emits valid code again, and calling a mutating method through a nested field updates the original value instead of a discarded copy.

### Long loops and tooling
kind: fix
Temporaries created inside loops no longer reserve stack per iteration, builtins on module-level vectors dispatch the real implementations, and the run command exits with the program's exit code.

## Breaking changes
- None.

## Known issues
- Comparing containers with equality operators is pointer identity: two equal vectors compare unequal, and equal result-of-vector values compare unequal; deep container equality is designed and queued.
- A confined allocation followed by a free can spin in the guard heap; keep the exit block as the last statement and avoid manual free until the runtime patch lands.
- Hot reload benchmarks that enter confined blocks remain slow while the trampoline cost is worked through.
