# v0.62.1

## Summary
A small follow-up release that clears the blockers reported by the benchmark
and playground lanes since v0.62.0.

## Highlights

### Numeric parsing works with dynamic libraries
kind: fix
Programs that combine numeric parsing with dynamic-library calls (for example
xiom.num together with xiom.ffi.dl) now compile and run. A string helper
invoked inside the standard library's integer parser could previously emit a
call to an internal symbol that was never defined.

### A function you define is no longer mistaken for C
kind: compiler
The safety check for foreign calls now only flags calls that really reach a
foreign declaration. Ordinary standard-library code that shares a name with a
C function (such as abs) passes cleanly again.

### No more spurious optimizer warning
kind: tooling
The compiler no longer prints "LLVM IR verification failed" on systems with
LLVM 18, where the optimizer's legacy flag spelling was removed. IR
verification now works on both old and new LLVM, and unsupported verifiers
are skipped quietly.

### The playground build ships with its JavaScript bindings
kind: tooling
The browser build of the compiler now ships with its JavaScript module and
type definitions, so the playground can load the current compiler directly.

## Breaking changes

- None.
