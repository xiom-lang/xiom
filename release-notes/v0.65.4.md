# v0.65.4

## Summary
Fixes the post-release aggregate-drop dominance failure and restores compile performance on large programs.

## Highlights

### Aggregate drop GEPs dominate nested arms
kind: compiler
An aggregate binding with a Vec field created inside a conditional arm emitted its drop-time field GEP in a block reachable without the arm's alloca, so clang rejected the IR (the epos package). The field and Vec-data GEPs are registered in the entry block and the current data pointer is still loaded at drop time, so growth/realloc reclamation is preserved.

### Large-program compile performance
kind: compiler
The per-function ownership prepass rebuilt and cloned program-global catalogs for every function. With the engine's twelve thousand injected declarations this was quadratic and a full editor build never finished. Those sets are now built once per compile and shared, and the editor emits its IR and links in minutes.

## Breaking changes
- None.

## Known issues
- Map/JSON/enum-tree retention (REL-1704) is the next memory slice.
- Vec[Str] element strings and removal containers are not yet reclaimed.
- By-value aggregate parameters are caller-transferred for retaining callees; callee-side parameter drops remain future work.
- A cold full editor build is still a long compile (dependency C/C++ included); it now completes instead of stalling.
