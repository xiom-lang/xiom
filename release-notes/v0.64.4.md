# v0.64.4

## Summary
Reliability release: strict name resolution and module isolation, function-value marshalling, safer install paths, and numeric narrowing for float vector stores.

## Highlights

### Stricter name resolution and imports
kind: compiler
A bare call now binds the calling module's own definition, including private helpers, so a same-named function elsewhere can no longer hijack it, the defect class behind a startup crash in a service harness. Private constants stay private, and an unresolved import is one clear error instead of a silent phantom.

### Function values survive every boundary
kind: compiler
Function-typed values marshal correctly through C calls, struct fields, locals and vector elements: callbacks re-pass cleanly, element calls of any arity return their declared type, and module-scope function pointers can be called and reassigned.

### Safer installs and one packages home
kind: tooling
Install commands refuse mangled or relative home paths with a clear error instead of scattering directories, archive extraction is deterministic, and when several home candidates exist the compiler picks the one that actually holds installed packages.

### Float vector stores convert their values
kind: fix
Writing a literal into a float vector element now converts it to the element type: 7.0 into a Float32 slot stores 7 rather than zero, and integer literals convert numerically instead of being reinterpreted as bit patterns.

## Breaking changes
- None.

## Known issues
- Comparing containers with equality operators is pointer identity: two equal vectors compare unequal, and equal results containing vectors compare unequal; deep container equality is queued.
- A confined allocation followed by a free can spin in the guard heap; keep the exit block as the last statement and avoid manual free until the runtime patch lands.
