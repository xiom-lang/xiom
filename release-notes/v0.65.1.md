# v0.65.1

## Summary
A memory-ownership release: owned vectors are reclaimed at scope exits, and the UI text pipeline stops growing its per-frame footprint.

## Highlights

### Owned vectors are freed at scope exit
kind: compiler
Fresh and call-return vectors, match-bound result payloads, and aggregate fields are now reclaimed at loop, match, and function exits. Long-running editors and scripting workloads no longer grow without bound.

### Text rendering stays flat
kind: fix
The font-shaping and glyph-raster wrappers declare caller-owned return buffers, and unsafe foreign calls no longer hide transient vectors from the drop pass. A 1,200-frame animated UI soak holds steady instead of reaching the memory cap.

### Element access keeps vector ownership
kind: compiler
Reading or writing a vector element no longer marks the whole vector as escaping, so per-iteration scratch vectors are reclaimed while taking an element reference still escapes.

### UI builds link with the new allocator path
kind: fix
Main-heap allocations in ownership-contract functions use the C allocator directly, so UI applications link against older runtime objects and no longer fail with a linker error.

## Breaking changes
- None.

## Known issues
- An actually-taken retry in a function that rebinds an owned vector can leak only the replaced buffer; the returned buffer is still caller-owned.
- Microcontroller targets use a bump allocator and do not support exceptions; vendor peripherals are not emulated.
