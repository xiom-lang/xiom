# v0.63.1

## Summary
A fixes-only release: runtime contract checks and the SMT verifier accept true contracts again, duplicate-leaf LZ4 calls bind correctly, and the catalog flush is measurably faster.

## Highlights

### Runtime contract checks stop rejecting true clauses
kind: fix
Ensures clauses that read tuple components (result.value.1) or compare a payload length with a parameter length could abort at runtime although they were structurally true. Contract-check compilation no longer leaks binding state between clauses, and a user local named result is isolated.

### Verifier emits valid SMT for receiver contracts
kind: fix
xiom-verify declared the method receiver inconsistently and scoped the owner sort inside a push, so z3 rejected whole scripts with "unknown constant self" and "unknown sort". Receivers are now declared per section, owner sorts are predeclared, and passing self to a reference parameter is coerced.

### LZ4 duplicate-leaf calls bind the right function
kind: fix
A bare lz4_compress call bound the Result-returning wrapper in codegen while the checker resolved the Vec-returning module function. Bare calls whose leaf has two different-signature owners now bind the checker's target; no stdlib rename is required.

### Faster catalog flush
kind: compiler
Catalog-body checking skips use declarations the module body never references, guarded so a body's bare type surface stays self-contained. In-container: catalog-body time 0.24s to 0.19s and scripting warm-index wall 1237ms to 996ms.

### Polluted installs no longer double-index the stdlib
kind: fix
A merged side-by-side install (lib/lib/xiom beside lib/xiom) produced one "declared by 2 files" warning per module and doubled index work. The catalog walk now skips the nested copy and keeps the canonical outer tree.
