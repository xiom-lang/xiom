# v0.64.7

## Summary
Win64 C ABI aggregates and typed confined faults, host-arch native targeting, builtin-shadow and fn-value fixes, duplicate-flag recovery, same-call borrow accuracy, and truly cold benchmark lanes -- on the stdlib-v0.64.7 pin.

## Highlights

### Win64 C ABI aggregates + typed confined faults
kind: compiler
On x86_64-pc-windows-msvc, by-value aggregates and returns use the MSVC C convention (pointer operand / sret; raw Int as fn casts share the C fn-pointer type); SysV/AArch64 keep the internal convention. Confined faults surface as typed HardwareFaults; unacknowledged faults exit 70. Only guard-page transients retry.

### Host-arch native targeting (linux-arm64 enabler)
kind: fix
Target::Native now follows the host architecture instead of assuming x86_64-linux, and the toolchain resolver carries the linux-arm64 asset names/sums. The arm64 release leg and the packages edge lane can target the host directly.

### Builtin shadow, fn-value, CLI and borrow fixes
kind: fix
Scalar .hash() and the Mutex barrier stop shadowing declarations; module-global fn vars emit their thunk, fn struct fields keep the uniform ENV layout, and fn aliases dispatch by resolved signature; duplicate value flags exit 2 cleanly; E001 no longer double-reports one borrow site. Genuine reuse still warns.

### Benchmark cold lanes stay cold
kind: compiler
--no-cache now disables the persistent catalog index and catalog-body check caches (read and write) in the compile, AOT-run, and in-process JIT paths. A lock proves the control run writes checkbodies.txt while cold runs write neither checkbodies.txt nor catidx.txt.

## Breaking changes
- None.

## Known issues
- Int128 division and modulo in a Vec loop can still access-violate; the fix is in progress.
- A capture-frames probe can hang on the run leg; a minimized repro is being collected.
- Send/Sync markers are declared and auto-derived but not yet enforced on spawn captures.
- Deep container equality remains pointer identity (carried from v0.64.6).
- The dependency-object cache key is consumer-specific, and a cache HIT does not verify object existence under concurrent builds, so concurrent compiles can hit a link failure.
