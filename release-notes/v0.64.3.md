# v0.64.3

## Summary
Correctness and performance release: hardened bounds and null checks, by-reference generics, allocation helpers, and faster warm recompiles.

## Highlights

### Bounds and null checks for hardened builds
kind: compiler
Building with overflow checks now guards fixed-array indexing and raw-pointer dereferences, so out-of-range accesses and null reads trap with a clear fault instead of silently corrupting memory.

### Warm recompiles skip unchanged library checks
kind: tooling
The compiler caches clean type-check results for the standard library between runs, so repeated builds of the same project no longer re-check unchanged library code. Run-path scratch files are also kept out of the module index, cutting cold index time.

### References to optional and result values read correctly
kind: compiler
Generic helpers that take references to optional or result values now read tags and payloads correctly, and passing a slice where a vector is expected compiles through the new bridge instead of being rejected.

### Your alloc and free helpers stay yours
kind: compiler
Functions named alloc or free in user code now bind to the local definition instead of the guard allocator, so confined blocks that wrap custom allocation run the intended code.

## Breaking changes
- None.

## Known issues
- Comparing containers with equality operators is pointer identity: two equal vectors compare unequal, and equal results containing vectors compare unequal; deep container equality is queued.
- A confined allocation followed by a free can spin in the guard heap; keep the exit block as the last statement and avoid manual free until the runtime patch lands.
